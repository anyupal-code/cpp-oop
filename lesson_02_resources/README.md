## 2.1. RAII

**RAII (Resource Acquisition Is Initialization)** — ресурс захватывается
в конструкторе и освобождается в деструкторе. Объект на стеке живёт
ровно столько, сколько нужно, и при выходе из области видимости
деструктор гарантированно освободит ресурс.

Это главная идиома C++: она работает при любом выходе из функции —
обычном возврате, `return` из середины, исключении.

```cpp
class File {
    std::FILE* f_;
public:
    explicit File(const char* path) : f_(std::fopen(path, "r")) {
        if (!f_) throw std::runtime_error("cannot open file");
    }
    ~File() { if (f_) std::fclose(f_); }
    std::FILE* get() const { return f_; }
};

void read(const char* path) {
    File f(path);        // ресурс захвачен
    // ... чтение ...
}                        // деструктор закроет файл — при любом выходе
```

Без RAII то же самое писали бы через `open` / `close` вручную и
рисковали забыть `close` на одной из веток.

Пример: `raii.cpp`.

## 2.2. Правило трёх / пяти

Если класс **владеет** ресурсом (сырой указатель, файл, сокет),
компиляторные копии по умолчанию сделают поверхностное копирование:
два объекта будут указывать на один ресурс и оба попытаются его
освободить. Результат — двойное освобождение (`double free`) или
утечка.

Поэтому нужно явно определить (или запретить через `= delete`):

1. **деструктор** — освобождает ресурс;
2. **конструктор копирования** — глубоко копирует ресурс;
3. **оператор присваивания копированием** — освобождает старый
   ресурс, копирует новый.

Это **правило трёх**. С C++11 к нему добавляются:

4. **конструктор перемещения**;
5. **оператор присваивания перемещением**.

Перемещение забирает ресурс у временного объекта, не копируя его.
Вместе — **правило пяти**.

```cpp
class Buffer {
    int* data_;
    std::size_t size_;
public:
    explicit Buffer(std::size_t n)
        : data_(new int[n]()), size_(n) {}

    ~Buffer() { delete[] data_; }                            // 1

    Buffer(const Buffer& o)                                  // 2
        : data_(new int[o.size_]), size_(o.size_) {
        std::copy(o.data_, o.data_ + size_, data_);
    }

    Buffer& operator=(const Buffer& o) {                     // 3
        if (this != &o) {
            delete[] data_;
            size_ = o.size_;
            data_ = new int[size_];
            std::copy(o.data_, o.data_ + size_, data_);
        }
        return *this;
    }
};
```

Если класс не должен копироваться вообще — проще запретить:

```cpp
Buffer(const Buffer&)            = delete;
Buffer& operator=(const Buffer&) = delete;
```

Пример: `rule_of_five.cpp`.

## 2.3. Умные указатели

Обёртки над сырыми указателями, реализующие RAII. Убирают ручной
`delete` и делают владение явным.

- **`std::unique_ptr<T>`** — единоличное владение. Не копируется,
  только перемещается. Основной инструмент.
- **`std::shared_ptr<T>`** — совместное владение через счётчик ссылок.
  Ресурс освобождается, когда счётчик дойдёт до нуля. Нужен реже.
- **`std::weak_ptr<T>`** — слабая ссылка: не владеет, не увеличивает
  счётчик. Нужна, чтобы разрывать циклы в `shared_ptr`.

```cpp
#include <memory>

auto p = std::make_unique<Point>(1, 2);     // unique_ptr
auto s = std::make_shared<Point>(3, 4);     // shared_ptr

// auto copy = p;                            // ошибка: unique_ptr не копируется
auto moved = std::move(p);                   // OK: владение перешло в moved
```

Правило: по умолчанию — `unique_ptr`. `shared_ptr` — только когда
владение действительно общее.

Пример: `smart_pointers.cpp`.

## 2.4. Исключения

Механизм обработки ошибок без кодов возврата. `throw` выбрасывает
исключение, `try` / `catch` его перехватывают.

```cpp
try {
    throw std::runtime_error("something failed");
} catch (const std::exception& e) {
    std::cout << "error: " << e.what() << "\n";
}
```

Ключевое:

- исключения работают в паре с RAII: при раскрутке стека деструкторы
  локальных объектов вызываются автоматически;
- ловить по `const std::exception&` — чтобы не срезать наследников;
- не бросать исключения в деструкторе.

Пример: `exceptions.cpp`.
