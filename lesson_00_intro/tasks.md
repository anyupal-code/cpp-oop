## 0.1. Что такое ООП

**Задание 1.** Своими словами (2–3 предложения): чем объектный подход
отличается от процедурного? В чём его выгода при росте программы?

**Ответ.** В процедурном подходе данные и функции, которые с ними
работают, лежат отдельно: изменил структуру данных — надо править все
функции, которые её используют. В объектном данные и поведение собраны
в одну сущность (класс), и изменение затрагивает только её. Выгода при
росте программы: меньше связности между частями, легче менять и
переиспользовать код.

**Задание 2.** Приведите пример из жизни: сущность, у которой есть
состояние и поведение.

**Ответ.** Чайник: состояние — `temperature`, `isOn`, `waterLevel`;
поведение — `heat()`, `pour()`, `turnOff()`. Внешний код не должен
напрямую писать `temperature = 500` — он вызывает `heat()`, а внутри
уже проверяется предел.

## 0.2. Класс и объект

**Задание 1.** Опишите класс `Book` с полями `title`, `author`, `year`.
Создайте два объекта с разными значениями.

**Ответ.**

```cpp
#include <iostream>
#include <string>

class Book {
    std::string title_, author_;
    int year_;
public:
    Book(std::string t, std::string a, int y)
        : title_(std::move(t)), author_(std::move(a)), year_(y) {}

    void print() const {
        std::cout << title_ << " — " << author_ << ", " << year_ << "\n";
    }
};

int main() {
    Book a{"Война и мир", "Толстой", 1869};
    Book b{"Преступление и наказание", "Достоевский", 1866};
    a.print();
    b.print();
}
```

**Задание 2.** Что произойдёт с полями одного объекта, если изменить
поля другого? Почему?

**Ответ.** Ничего не произойдёт. `a` и `b` — независимые объекты, каждый
со своими полями. Класс — это тип (чертёж), а объекты — отдельные
экземпляры, у каждого своя память под поля.

## 0.3. Четыре принципа

**Задание 1.** Для каждого из четырёх принципов (инкапсуляция,
абстракция, наследование, полиморфизм) приведите по одному примеру
из реального мира (не из программирования).

**Ответ.**

- **Инкапсуляция** — банкомат: нельзя напрямую изменить баланс на счёте,
  только через операции `deposit`/`withdraw`.
- **Абстракция** — водитель: руль, педали, коробка передач. Не нужно
  знать, как устроен двигатель, чтобы ехать.
- **Наследование** — «собака» и «кошка» — частные случаи «животного»:
  у них есть общее (дышат, едят) и своё (лают / мяукают).
- **Полиморфизм** — кнопка «play» на разных устройствах: у плеера,
  телевизора, колонки действие своё, но интерфейс один.

**Задание 2.** Какой принцип отвечает за защиту данных от внешнего
изменения?

**Ответ.** Инкапсуляция.

## 0.4. Словарь

**Задание 1.** Не подглядывая в README, объясните: чем конструктор
отличается от обычного метода? Чем геттер отличается от сеттера?

**Ответ.** Конструктор — специальный метод, вызывается автоматически при
создании объекта, служит для инициализации. Обычный метод вызывается
вручную и может вызываться много раз. Геттер читает поле и не меняет
объект (обычно `const`), сеттер пишет в поле и может валидировать
значение.

**Задание 2.** Что такое «интерфейс класса»?

**Ответ.** Интерфейс класса — набор его `public`-методов: то, что
доступно снаружи. По интерфейсу пользователь класса понимает, *что*
объект умеет, не зная, *как* это устроено внутри.

## 0.5. Синтаксис

**Задание 1.** Напишите класс `Counter` с методами `inc()`, `dec()`,
`value()`. Проверьте работу через объект и через указатель (`->`).

**Ответ.**

```cpp
#include <iostream>

class Counter {
    int value_ = 0;
public:
    void inc()         { ++value_; }
    void dec()         { --value_; }
    int  value() const { return value_; }
};

int main() {
    Counter c;
    c.inc();
    c.inc();
    std::cout << c.value() << "\n";   // 2

    Counter* p = &c;
    p->dec();
    std::cout << p->value() << "\n";  // 1
}
```

**Задание 2.** Объясните, зачем в `int value() const` стоит `const`.

**Ответ.** `const` после списка параметров означает, что метод не меняет
поля объекта. Это:

- даёт компилятору проверить, что вы случайно не измените состояние;
- позволяет вызывать метод у `const`-объектов и `const`-ссылок
  (`void print(const Counter& c) { c.value(); }` — без `const`
  не скомпилируется).
