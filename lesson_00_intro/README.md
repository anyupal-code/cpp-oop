## 0.1. Что такое ООП и зачем оно

**ООП (объектно-ориентированное программирование)** — парадигма, в которой
программа строится из **объектов**, а не из функций и глобальных данных.

Каждый объект:
- **хранит своё состояние** (данные);
- **умеет выполнять действия** (методы);
- **скрывает внутреннее устройство** от внешнего мира.

**Зачем:** когда программа растёт, процедурный код (функции + глобальные
данные) становится трудно менять — любое изменение данных ломает функции,
которые с ними работают. ООП связывает данные и поведение в одну сущность,
и изменение затрагивает только её.

### Процедурный vs объектный подход

**Процедурный:** данные и функции разделены.

```cpp
struct Point { int x, y; };
void move(Point& p, int dx, int dy) { p.x += dx; p.y += dy; }
void print(const Point& p)          { /* ... */ }
```

**Объектный:** данные и функции — внутри одной сущности.

```cpp
class Point {
    int x, y;
public:
    void move(int dx, int dy) { x += dx; y += dy; }
    void print() const        { /* ... */ }
};
```

Результат один и тот же, но во втором случае `Point` — целостная сущность,
а не набор разрозненных полей и функций.

Пример: `procedural_vs_object.cpp`.

## 0.2. Класс и объект

**Класс** — это **тип**. Описание: какие данные будут у объекта и какие
методы он умеет выполнять. Сам по себе класс — не объект, а «чертёж».

**Объект** — это **экземпляр класса**. Конкретная вещь, созданная по чертежу,
со своими значениями полей.

Аналогия: `class` — чертёж дома, объект — сам дом. По одному чертежу можно
построить много домов (объектов), и у каждого будет своё состояние.

```cpp
class Point {           // класс (тип)
    int x, y;
public:
    Point(int x_, int y_) : x(x_), y(y_) {}
};

int main() {
    Point a{1, 2};      // объект №1
    Point b{3, 4};      // объект №2 — другой, независимый
}
```

`a` и `b` — разные объекты одного класса. Изменение `a.x` не затронет `b.x`.

Пример: `class_and_object.cpp`.

## 0.3. Четыре принципа ООП

Четыре принципа, на которых держится ООП. В курсе они раскрываются
постепенно, здесь — только суть.

| Принцип | Суть | Где в курсе |
|---------|------|-------------|
| **Инкапсуляция** | Скрыть внутреннее состояние, дать доступ только через методы | `lesson_01_object`, тема 1.2 |
| **Абстракция** | Выделить главное, отбросить детали; работать через интерфейс | `lesson_01_object` + `lesson_03_hierarchy` |
| **Наследование** | Новый класс на базе существующего, переиспользование кода | `lesson_03_hierarchy`, тема 3.1 |
| **Полиморфизм** | Один интерфейс — разные реализации; выбор в рантайме | `lesson_03_hierarchy`, тема 3.2 |

**Инкапсуляция** — данные `private`, доступ через `public`-методы.
Защита от некорректного изменения извне.

**Абстракция** — пользователь класса видит только методы, не детали
реализации. Ему не важно, *как* устроен `Account::deposit`, важно *что*
он делает.

**Наследование** — `Dog` наследует `Animal`: получает его поля и методы,
добавляет свои.

**Полиморфизм** — через указатель `Animal*` можно вызвать `speak()`,
и у `Dog` сработает `Dog::speak`, у `Cat` — `Cat::speak`.

Пример: `four_principles.cpp`.

## 0.4. Словарь терминов

Краткий глоссарий. К каждому термину в курсе будет свой урок.

| Термин | Значение |
|--------|----------|
| **Класс** | Пользовательский тип: данные + методы |
| **Объект** | Экземпляр класса |
| **Поле** (member) | Переменная внутри класса |
| **Метод** | Функция внутри класса |
| **Конструктор** | Метод, вызываемый при создании объекта |
| **Деструктор** | Метод, вызываемый при уничтожении объекта |
| **Инкапсуляция** | Сокрытие состояния, доступ через методы |
| **Интерфейс** | Набор `public`-методов класса |
| **Геттер** | Метод чтения поля (`getX()`) |
| **Сеттер** | Метод записи поля (`setX()`) |
| **Наследование** | Создание класса на базе другого |
| **Базовый класс** | Родитель, от которого наследуют |
| **Производный класс** | Наследник |
| **Виртуальная функция** | Метод, переопределяемый в наследниках |
| **Полиморфизм** | Один интерфейс — разные реализации |
| **Абстрактный класс** | Класс с чисто виртуальным методом, нельзя создать объект |
| **RAII** | Идиома: ресурс в конструкторе, освобождение в деструкторе |
| **Умный указатель** | Обёртка над указателем с автоматическим управлением памятью |
| **RTTI** | Информация о типе во время выполнения |

## 0.5. Как ООП выглядит в C++

В C++ класс объявляется через `class` или `struct`.
Доступ к полям — через `.` (объект) или `->` (указатель).

```cpp
class Counter {
    int value_ = 0;        // поле (private по умолчанию)
public:
    void inc()         { ++value_; }   // метод
    int  value() const { return value_; }
};

int main() {
    Counter c;             // объект
    c.inc();               // вызов метода через .
    c.inc();
    std::cout << c.value(); // 2

    Counter* p = &c;       // указатель на объект
    p->inc();              // вызов метода через ->
    std::cout << p->value(); // 3
}
```

Ключевое:
- `class` — по умолчанию `private`, `struct` — по умолчанию `public`
  (это единственное техническое отличие);
- `.` — доступ к члену объекта, `->` — доступ к члену через указатель;
- `const` после метода означает, что метод не меняет состояние объекта.

Пример: `counter.cpp`.
