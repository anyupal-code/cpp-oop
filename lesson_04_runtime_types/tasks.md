# Урок 04. Типы в рантайме — задания и ответы

---

## 4.1. Приведение типов

**Задание 1.** Перечислите четыре вида приведения в C++ и для чего
каждый нужен.

**Ответ.**

- `static_cast` — обычные преобразования (числа, указатели в иерархии
  вниз при уверенности). Проверка на этапе компиляции.
- `dynamic_cast` — безопасное приведение в полиморфной иерархии.
  Проверка в рантайме, при ошибке — `nullptr`.
- `const_cast` — снятие `const`/`volatile`.
- `reinterpret_cast` — переинтерпретация битов. Опасно, нужно редко.

**Задание 2.** Чем `static_cast` отличается от `dynamic_cast`
при приведении вниз в иерархии?

**Ответ.** `static_cast` не проверяет реальный тип: если объект на
самом деле другого наследника, получите некорректный указатель —
undefined behavior при использовании. `dynamic_cast` проверяет
в рантайме и возвращает `nullptr`, если тип не совпал.

**Задание 3.** Почему `dynamic_cast` не работает с классами без
виртуальных функций?

**Ответ.** `dynamic_cast` использует RTTI, а RTTI для полиморфных
классов хранится в таблице виртуальных функций. Без виртуальных
функций этой информации нет, и приведение не скомпилируется.

**Задание 4.** Когда нужен `const_cast`?

**Ответ.** Когда есть `const`-ссылка или указатель, а вызываемая
функция требует не-`const` (обычно из-за плохо спроектированного
API). Снимать `const` с объекта, который изначально был объявлен
`const`, и затем его менять — undefined behavior.

## 4.2. RTTI

**Задание 1.** Что такое RTTI и какие два инструмента он даёт?

**Ответ.** RTTI — информация о типе во время выполнения. Инструменты:
`dynamic_cast` (безопасное приведение вниз) и `typeid` (объект
`std::type_info` с информацией о типе).

**Задание 2.** Что вернёт `typeid` для полиморфного объекта,
на который есть указатель базового класса?

**Ответ.** Динамический тип — реальный тип объекта, а не тип
указателя. Например, если `Animal* a = new Dog;`, то
`typeid(*a).name()` вернёт имя `Dog`.

**Задание 3.** Почему `typeid` и `dynamic_cast` часто считают
«кодом с запашком»? Когда их всё же стоит использовать?

**Ответ.** Обычно их применяют там, где правильнее виртуальная
функция: добавили бы `virtual`-метод и не проверяли бы тип вручную.
Ветвление по типу через `typeid`/`dynamic_cast` нарушает открытость
к расширению — при добавлении наследника нужно править все такие
ветвления. Оправданы они, когда иерархия чужая (нельзя добавить
метод) или когда типов много и виртуальный метод в каждый неудобен.

**Задание 4.** Напишите функцию, которая через `dynamic_cast`
проверяет, является ли `Animal*` собакой, и если да — вызывает
`bark()`.

**Ответ.**

```cpp
void tryBark(Animal* a) {
    if (auto* d = dynamic_cast<Dog*>(a)) {
        d->bark();
    }
}
```
