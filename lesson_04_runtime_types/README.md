# Урок 04. Типы в рантайме

Как безопасно приводить типы в иерархии и получать информацию о типе
во время выполнения.

Темы:
- 4.1. Приведение типов
- 4.2. RTTI

---

## 4.1. Приведение типов

В C++ четыре вида приведения, каждый — под свою задачу. В отличие
от C-style `(T)x`, они явно говорят, **что** и **зачем** преобразуется,
и компилятор может проверить корректность.

| Приведение | Когда использовать | Проверка |
|------------|--------------------|----------|
| `static_cast<T>(x)` | Обычные преобразования: числа, указатели в иерархии вниз (downcast) при уверенности | Компиляция |
| `dynamic_cast<T>(x)` | Безопасное приведение в полиморфной иерархии | Рантайм |
| `const_cast<T>(x)` | Снятие `const` / `volatile` | — |
| `reinterpret_cast<T>(x)` | Переинтерпретация битов (указатель ↔ число и т.п.) | — |

```cpp
double d = 3.7;
int    i = static_cast<int>(d);          // 3, обычное преобразование

int*   p = &i;
void*  v = p;
int*   q = static_cast<int*>(v);         // обратно к int*

const int ci = 5;
int& r = const_cast<int&>(ci);           // снять const (осторожно!)
```

`reinterpret_cast` — самый опасный: не меняет биты, только
интерпретацию. Нужен редко (сериализация, работа с железом).
В обычном коде его избегают.

### `static_cast` vs `dynamic_cast` в иерархии

```cpp
class Animal { public: virtual ~Animal() = default; };
class Dog : public Animal { public: void bark() const {} };
class Cat : public Animal {};

void f(Animal* a) {
    Dog* d1 = static_cast<Dog*>(a);   // компилятор не проверяет
    Dog* d2 = dynamic_cast<Dog*>(a);  // проверка в рантайме:
                                      // nullptr, если a — не Dog
}
```

- `static_cast` быстрее, но если `a` на самом деле `Cat`,
  получите указатель на «собаку», которая на самом деле кошка —
  undefined behavior при использовании.
- `dynamic_cast` возвращает `nullptr`, если тип не совпал —
  безопасно, но работает только для полиморфных классов
  (с хотя бы одной виртуальной функцией).

Пример: `casts_rtti.cpp`.

## 4.2. RTTI

**RTTI (Run-Time Type Information)** — механизм получения информации
о типе во время выполнения. Два инструмента:

- **`dynamic_cast`** — безопасное приведение вниз (см. 4.1).
- **`typeid(x)`** — объект `std::type_info` с информацией о типе;
  умеет сравниваться и печатать имя.

```cpp
#include <typeinfo>

void f(Animal& a) {
    std::cout << typeid(a).name() << "\n";   // реальный тип в рантайме
    if (typeid(a) == typeid(Dog)) { /* ... */ }
}
```

`typeid` работает и с неполиморфными типами, но для полиморфного
объекта возвращает **динамический** тип (тот, что на самом деле),
а не статический (тип ссылки/указателя).

**Когда RTTI нужен:** редко. Чаще вместо `typeid`/`dynamic_cast`
используют виртуальные функции — они дают тот же результат без
ветвлений по типу. RTTI оправдан, когда иерархия чужая или типов
много и добавлять виртуальный метод в каждый неудобно.

Пример: `casts_rtti.cpp`.
